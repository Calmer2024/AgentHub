## 2. Design Read

AgentHub 应被设计成“AI Agent 工程工作台”，不是普通聊天软件，也不是营销型 AI 工具页。目标用户是长期高频使用的工程、产品、设计与运营团队成员，他们需要在一个界面中理解项目、调度 Agent、查看文件、审查输出、处理运行状态。

设计语言应是：

| 维度 | 建议 |
| --- | --- |
| 核心气质 | 专业、克制、锋利、可信、持续可用 |
| 视觉类型 | 深色优先、浅色同等可用的工程工作台，IM 与 IDE 混合形态 |
| 信息密度 | 高密度，但必须有清晰层级 |
| 情绪表达 | 少装饰，多状态，多上下文 |
| 目标观感 | 接近 Coze 截图中“工作台已经打开、资源已经就位、用户能马上开始”的成熟感 |

三项设计旋钮建议：

| 旋钮 | 值 | 解释 |
| --- | --- | --- |
| 视觉变化度 | 4/10 | 需要稳定、耐用，不追求艺术化布局 |
| 动效强度 | 3/10 | 以反馈和状态转场为主，不做戏剧化动效 |
| 信息密度 | 8/10 | 目标是专业工具，不是留白型展示页 |

## 3. 产品定位下的视觉北极星

AgentHub 的界面北极星是：

> 让用户感觉自己进入了一个可运行、可审查、可交付的 AI 工程控制台。

这句话会影响所有视觉决策：

1. 聊天区不只是聊天，应像任务流。
2. 文件区不只是附属面板，应像项目上下文。
3. Agent 不只是联系人，应像可调度的工作角色。
4. 运行状态不只是提示，应像系统仪表。
5. 产物不只是卡片，应像可继续处理的交付物。

因此，AgentHub 的视觉不应追求“可爱 AI”“梦幻渐变”“大面积玻璃拟态”，而应追求“像专业工具一样安静、清楚、可信”。

## 4. Coze 截图的可借鉴设计点

用户提供的 Coze 截图有几个非常值得 AgentHub 学习的地方。

### 4.1 三层工作台结构很明确

截图中可以看到：

1. 最左侧是窄 rail，承载全局入口。
2. 左侧是会话列表，承载对话切换。
3. 中间是主对话与输入区。
4. 右侧是文件、版本、代码、终端输出。

这让用户马上知道：这是一个集聊天、文件和运行环境于一体的工作台。AgentHub 已经具备类似骨架，但需要在视觉上更明确地表达“三层工作空间”：

| 层级 | AgentHub 建议 |
| --- | --- |
| 全局层 | 用更窄、更稳定的 rail 承载全局导航和账户状态 |
| 项目/会话层 | 左侧列表应更像项目内导航，而不是普通 IM 联系人列表 |
| 工作层 | 聊天、文件、运行状态应组成一个完整 workspace，不要割裂 |

### 4.2 控件非常工具化

Coze 截图里大量使用 icon-only button、紧凑 tab、轻量分割线、顶部工具条。它没有把每个功能都做成大按钮，而是让工具面板保持专业密度。

AgentHub 应遵守同样原则：

1. 高频工具用 icon button，不用长文字按钮。
2. 文字按钮只用于明确提交动作，例如“预览”“保存”“发送”。
3. 次级工具放在 hover、更多菜单或 panel header 中。
4. 工具栏高度控制在 40-48px，避免占用主内容。

### 4.3 暗色不是纯黑，而是分层黑

Coze 截图使用的是多层深色：

1. 最底层接近黑。
2. 面板略微抬起。
3. 激活项有灰色高亮。
4. 分割线非常轻。

AgentHub 当前已经有深色 token，但面板有时偏“卡片化”，阴影和圆角略软。建议更偏向“深色分层平面”，用背景色、边框和 hover 来表达层级，减少大面积厚重阴影。

### 4.4 当前会话高亮有明确形状

Coze 截图中当前会话行有明确灰色高亮、圆角、头像和时间信息，用户能快速定位当前位置。

AgentHub 的会话列表应强化：

1. 当前项高亮要稳定，不依赖微妙边框。
2. 当前项不要过亮，以免抢走主工作区注意力。
3. 当前项左侧可用 2-3px accent bar，但不要每个卡片都使用强装饰。
4. 会话摘要、时间、Agent 名称要有清楚的文本层级。

### 4.5 文件区像 IDE，而不是弹窗

Coze 右侧文件区有文件树、代码编辑、终端输出，整体像一个轻量 IDE。AgentHub 既然定位 Project-first，就应该把文件区视觉做得更“原生工作台”，不要像临时 modal。

建议：

1. 文件树行高 28-32px，接近 IDE。
2. 文件 tab 高度 36-40px。
3. 代码编辑区用更低圆角和更强等宽字体规则。
4. 终端、输出、日志类区域要使用明确的 mono 体系。

## 5. AgentHub 当前视觉状态诊断

### 5.1 优势

| 方面 | 评价 |
| --- | --- |
| 整体方向 | 暗色工作台方向正确，适合 AI 工程产品 |
| Token 基础 | 已经有 `--ah-*` 设计 token，可沉淀为系统 |
| 工作台骨架 | Project、Session、Chat、Files 已经具备专业工具雏形 |
| 组件统一性 | 大量组件复用 `agenthub-*` 类名，说明系统化基础不错 |
| 高密度能力 | 当前界面可承载复杂 Agent、文件、Artifact、运行状态 |

### 5.2 主要问题

| 问题 | 表现 | 风险 |
| --- | --- | --- |
| 视觉层级偏软 | 卡片、圆角、阴影较多 | 看起来更像漂亮 demo，而不是长期工具 |
| 品牌识别偏弱 | 主 accent 过于灰白 | 缺少一眼记住的 AgentHub 信号 |
| 控件密度不稳定 | 同类按钮有圆形、圆角矩形、文字按钮混用 | 专业感下降 |
| 面板边界有时过重 | 多重圆角和嵌套 panel | 产生“卡片套卡片”的复杂感 |
| 动效缺少规范 | 已有 slide/popover，但没有统一动效语言 | 后续组件容易各自发挥 |
| 空态偏解释型 | 空态容易出现说明文字 | AI 工具应更强调下一步动作 |
| 文件区仍像附加层 | 文件工作台视觉还可以更接近 IDE | Project-first 感知不够强 |

### 5.3 设计债清单

后续做 UI 打磨时，优先处理这些设计债：

1. 统一圆角体系。
2. 统一 icon button 尺寸。
3. 统一 list row 高度和 active 态。
4. 统一主工作区 panel 背景。
5. 减少无意义阴影。
6. 建立 motion token。
7. 建立文件区和代码区的专用视觉规范。
8. 建立空态、加载态、错误态、运行态模板。

## 6. 视觉系统原则

### 6.1 专业优先

所有界面元素都要服务于工作效率。装饰只能用于表达层级或状态，不能只是为了“高级感”。

### 6.2 状态优先

AI Agent 产品最重要的是让用户知道系统在做什么。运行中、等待审批、已完成、失败、可恢复、未保存、可引用，这些状态要比装饰更显眼。

### 6.3 Project-first

视觉上要让用户持续感知当前 Project，而不是只看到当前会话。Project 名、文件入口、产物入口、运行状态应在界面中形成稳定锚点。

### 6.4 聊天即任务流

AgentHub 的聊天流不应像社交聊天，而应像任务流。消息气泡可以保留 IM 亲和力，但任务卡、产物卡、审批卡、运行卡应比普通文本更结构化。

### 6.5 深色优先，浅色同等可用

默认深色更符合工程工作台，但浅色主题不能只是“反色版”。AgentHub 的浅色主题也必须达到专业产品质感，适合白天办公、投屏演示、长文阅读和非技术团队使用。

浅色主题的设计目标：

1. 不做纯白刺眼后台，而做温和、清晰、轻量的生产力界面。
2. 保留 Project-first 和 IDE 工作台感，不因为变亮而变成普通 SaaS 表单页。
3. 通过浅灰背景、细边框、弱阴影和明确 active 态维持层级。
4. 代码区、终端区、文件树仍要有足够对比，不能被“白色卡片化”冲淡。
5. 深浅主题必须共享同一组件结构、间距、圆角和动效，只替换 token。

## 7. 色彩规范

### 7.1 深色主题主色板

| 用途 | 建议色值 | 说明 |
| --- | --- | --- |
| App 背景 | `#0B0B0B` | 全局底色 |
| Rail 背景 | `#101010` | 全局导航 |
| Sidebar 背景 | `#121212` | 会话和项目列表 |
| 主工作区背景 | `#0E0E0E` | 聊天和文件底层 |
| Panel 背景 | `#181818` | 稳定面板 |
| Panel raised | `#202020` | 浮层、菜单、选中项 |
| Hover 背景 | `rgba(255,255,255,0.07)` | 列表和按钮 hover |
| Active 背景 | `rgba(255,255,255,0.11)` | 当前会话、当前 tab |
| 分割线 | `rgba(255,255,255,0.10)` | 默认边界 |
| 强分割线 | `rgba(255,255,255,0.18)` | focus、选中、拖拽 |

### 7.2 浅色主题主色板

浅色主题不应使用纯白铺满所有层级。建议使用“柔白底 + 冷灰面板 + 轻边框”的体系，让界面保持工具感。

| 用途 | 建议色值 | 说明 |
| --- | --- | --- |
| App 背景 | `#F6F7F9` | 全局底色，避免纯白刺眼 |
| Rail 背景 | `#FFFFFF` | 全局导航，边界清楚 |
| Sidebar 背景 | `#FFFFFF` | 会话和项目列表 |
| 主工作区背景 | `#F8F9FB` | 聊天和文件底层 |
| Panel 背景 | `#FFFFFF` | 稳定面板 |
| Panel raised | `#F1F3F6` | 浮层、选中项、代码 header |
| Hover 背景 | `#F1F3F6` | 列表和按钮 hover |
| Active 背景 | `#E9EDF3` | 当前会话、当前 tab |
| 分割线 | `#E4E7EC` | 默认边界 |
| 强分割线 | `#CDD3DD` | focus、选中、拖拽 |

浅色主题规则：

1. 主背景不使用大面积纯白，纯白只给 panel 和内容承载区。
2. Sidebar 与主工作区之间要有明确但轻的分割线。
3. Active 态不能只靠深色文字，必须有背景或侧边线。
4. Hover 态要比 active 态弱一个层级。
5. Modal 和 popover 可使用纯白，但必须配合边框和轻阴影。

### 7.3 深色文本颜色

| 层级 | 建议色值 | 使用 |
| --- | --- | --- |
| Primary | `#F5F5F5` | 标题、关键内容 |
| Secondary | `#B8B8B8` | 描述、元信息 |
| Tertiary | `#7A7A7A` | 时间、计数、弱提示 |
| Disabled | `#555555` | 禁用态 |

### 7.4 浅色文本颜色

| 层级 | 建议色值 | 使用 |
| --- | --- | --- |
| Primary | `#151922` | 标题、关键内容 |
| Secondary | `#526070` | 描述、元信息 |
| Tertiary | `#8A94A3` | 时间、计数、弱提示 |
| Disabled | `#B8C0CC` | 禁用态 |

规则：

1. 浅色主题正文不能使用过浅灰，默认正文至少接近 `#151922`。
2. 辅助文本不低于 `#526070`，否则中文阅读会发虚。
3. 输入 placeholder 可用 `#9AA4B2`，但 label 必须更深。
4. 代码区文字需要独立 token，不直接复用普通正文灰。

### 7.5 品牌与状态色

AgentHub 需要一个比灰白更明确的品牌信号，但不能走泛 AI 紫色渐变。

| 类型 | 建议 | 用法 |
| --- | --- | --- |
| Brand accent | `#8FE7B8` 或 `#9EC5FF` 二选一 | 当前项侧边线、focus ring、运行高亮 |
| Success | `#8FD9AD` | 运行完成、在线 |
| Info | `#9EC5FF` | 文件、代码、系统提示 |
| Warning | `#E1C78D` | 审批、等待、未保存 |
| Danger | `#F2A0A0` | 错误、删除、失败 |

规则：

1. Brand accent 只能选一个作为全局主信号。
2. 状态色只用于状态，不用于装饰。
3. 不使用大面积紫蓝渐变作为 AI 感表达。
4. 头像可以多彩，但头像色不等于系统色。

### 7.6 深浅主题状态色映射

状态色不能直接在深浅主题中共用同一个背景透明度。浅色主题需要更浅的背景和更深的文字，深色主题需要更亮的文字和更透明的背景。

| 状态 | 深色文字 | 深色背景 | 浅色文字 | 浅色背景 |
| --- | --- | --- | --- | --- |
| Success | `#8FD9AD` | `rgba(143,217,173,.13)` | `#1F6F48` | `#EAF7F0` |
| Info | `#9EC5FF` | `rgba(158,197,255,.13)` | `#245D9B` | `#EAF2FF` |
| Warning | `#E1C78D` | `rgba(225,199,141,.14)` | `#7B5A20` | `#FFF6DE` |
| Danger | `#F2A0A0` | `rgba(242,160,160,.14)` | `#9B3333` | `#FFF0F0` |

### 7.7 浅色主题代码区

浅色主题最容易失败的区域是代码和终端。不能把代码区做成普通白卡片。

建议：

| 用途 | 建议色值 |
| --- | --- |
| Code 背景 | `#F6F8FB` |
| Code panel | `#EEF2F7` |
| Code header | `#E8EDF4` |
| Code border | `#D8DEE8` |
| Code text | `#222A36` |
| Line number | `#8C97A7` |
| Terminal 背景 | `#111318` |

规则：

1. 浅色主题可以保留深色终端，这是专业工具中合理的混合主题。
2. 代码编辑器可浅色，但终端输出建议深色，避免日志等级色失真。
3. 文件树与代码区之间的边界要比普通 panel 更清楚。
4. 语法高亮在浅色主题下要使用深色低饱和色，不用荧光色。

## 8. 字体与排版规范

### 8.1 字体体系

| 场景 | 建议 |
| --- | --- |
| UI 文本 | 系统 sans，保持跨平台清晰 |
| 代码、终端、路径 | JetBrains Mono、SF Mono、Consolas 之一 |
| 数字指标 | 可使用 tabular nums |

### 8.2 字号阶梯

| Token | 大小 | 行高 | 使用 |
| --- | --- | --- | --- |
| `text-11` | 11px | 16px | 辅助标签、时间、计数 |
| `text-12` | 12px | 18px | 元信息、tab 副文本 |
| `text-13` | 13px | 20px | 工具栏、列表摘要 |
| `text-14` | 14px | 22px | 默认 UI 正文 |
| `text-16` | 16px | 24px | 面板标题、会话标题 |
| `text-20` | 20px | 28px | 空态标题、页面级标题 |
| `text-24` | 24px | 32px | 少量核心空态，不用于面板内部 |

规则：

1. 工作台内不要使用 hero 级字号。
2. 标题和正文之间至少相差一个层级。
3. 中文正文行高不低于字号的 1.5 倍。
4. 文件树、代码行号、终端输出全部使用等宽字体。

## 9. 间距与栅格规范

### 9.1 基础单位

使用 4px 基础栅格。

| Token | 值 | 使用 |
| --- | --- | --- |
| `space-1` | 4px | icon 与文字微间距 |
| `space-2` | 8px | 小控件内部间距 |
| `space-3` | 12px | 列表项横向 padding |
| `space-4` | 16px | 面板内边距 |
| `space-5` | 20px | 模块间距 |
| `space-6` | 24px | 大面板边距 |

### 9.2 工作台尺寸

| 区域 | 建议 |
| --- | --- |
| 全局 rail | 52-64px |
| 会话列表 | 280-320px |
| 主聊天区 | 自适应，最小 420px |
| 文件工作区 | 420-560px，支持拖拽 |
| 顶部工具栏 | 44-52px |
| 底部输入区 | 76-120px |
| 文件树行高 | 28-32px |
| 会话列表行高 | 60-72px |

## 10. 圆角、边框与阴影规范

### 10.1 圆角系统

| 类型 | 圆角 | 使用 |
| --- | --- | --- |
| Shell panel | 22-24px | 主容器外框 |
| Panel/card | 14-18px | 面板、空态、列表组 |
| List row | 12-14px | 会话、项目、文件行 |
| Control | 8-10px | 工具按钮、输入框、菜单项 |
| Pill | 999px | segmented control、badge、主输入按钮 |
| Code/editor | 6-8px | 代码 tab、代码块、终端 |

规则：

1. 不要让代码编辑器使用 24px 大圆角。
2. 不要在同一层级混用 8px 与 28px。
3. 卡片内再套卡片时，内层必须更小圆角、更弱背景。

### 10.2 边框

1. 默认边框 1px。
2. 深色模式默认边框透明白 10-12%。
3. 浅色模式默认边框使用冷灰 `#E4E7EC`，不要用纯黑透明边框。
4. 选中和 focus 边框提升到 18-22% 或使用对应浅色强边框 `#CDD3DD`。
5. 不使用粗边框表达普通 hover。
6. 浅色主题中，边框比阴影更重要；深色主题中，背景层级比边框更重要。

### 10.3 阴影

阴影只用于浮层、菜单、modal、drag overlay。主工作台面板优先使用背景与边框表达层级。

| 层级 | 建议 |
| --- | --- |
| 主面板 | 无阴影或极弱阴影 |
| Popover/Menu | `0 16px 40px rgba(0,0,0,.28)` |
| Modal | `0 24px 70px rgba(0,0,0,.38)` |
| Hover 卡片 | 最多 `0 8px 20px rgba(0,0,0,.12)` |

浅色主题阴影规则：

| 层级 | 建议 |
| --- | --- |
| 主面板 | 不使用阴影，只使用边框 |
| Popover/Menu | `0 12px 32px rgba(24,34,50,.12)` |
| Modal | `0 24px 70px rgba(24,34,50,.16)` |
| Hover 卡片 | 最多 `0 8px 20px rgba(24,34,50,.08)` |

浅色主题里，阴影必须带一点冷灰色相，不使用纯黑大阴影。否则界面会从专业工具变成低质后台模板。

## 11. 布局规范

### 11.1 全局工作台

AgentHub 推荐采用固定工作台结构：

```text
Rail | Project/Session Sidebar | Chat Workspace | File/Output Workspace
```

规范：

1. 左侧区域应稳定，不在会话切换时跳动。
2. 主聊天区始终拥有最高可读性。
3. 文件区可打开、关闭、拖拽，但不应像临时弹窗一样漂浮失控。
4. 顶部 header 只保留上下文和高频工具。
5. 输入区固定底部，保持可预期。

### 11.2 左侧 rail

建议：

1. 宽度 56px 左右。
2. icon 统一 20px。
3. 当前入口用背景块或细 accent，不用大面积高亮。
4. 底部账户、升级、设置等入口统一停靠。
5. rail 不放长文字。

### 11.3 会话列表

建议：

1. 当前会话行使用稳定 active 背景。
2. 头像 40-44px，在线状态点 8-10px。
3. 标题 14px semibold，摘要 12px muted，时间 11px faint。
4. 每行只保留一个主要状态，不堆叠多个 badge。
5. hover 工具延迟显示，避免列表常态拥挤。

### 11.4 聊天工作区

建议：

1. 消息内容最大宽度控制在 760-860px。
2. assistant 消息偏结构化，user 消息可更像气泡。
3. 运行卡、审批卡、产物卡应有统一卡片结构。
4. 空态不要居中大字结束，应提供任务起手。
5. 输入框应成为视觉锚点，但不能像巨大弹窗。

### 11.5 文件工作区

建议：

1. 文件区视觉向 IDE 靠近，低圆角、高密度。
2. 文件树与代码编辑区域用 1px 分割线。
3. 顶部 tab 语义清楚，active tab 不要只靠颜色。
4. 终端与输出区域使用更强 mono 规则。
5. 文件区打开时，主聊天区不要被挤到不可读。

## 12. 组件设计规范

### 12.1 Button

| 类型 | 形态 | 使用 |
| --- | --- | --- |
| Primary | 高 36-44px，pill 或 12px radius | 登录、发送、保存、确认 |
| Secondary | 边框或 muted 背景 | 取消、打开、切换 |
| Icon button | 32-40px 方形或圆形 | 工具栏 |
| Danger | 状态色 + 确认文案 | 删除、终止 |

规则：

1. 同一工具栏 icon button 尺寸必须一致。
2. icon-only button 必须有 tooltip。
3. primary button 一个区域最多一个。
4. danger 不使用大面积红色，除非是最终确认。

### 12.2 List Row

列表行是 AgentHub 的关键组件，包括项目、会话、Agent、文件。

规范：

1. 高度使用固定区间，避免内容变化导致跳动。
2. active、hover、selected、unread 要明确区分。
3. active 表示当前位置，selected 表示操作选择，unread 表示新内容。
4. 不要用同一种高亮表达所有状态。

### 12.3 Composer

输入框是工作台最重要的控件。

建议：

1. 默认高度 56-64px，内容增多时最多扩展到 176px。
2. 附件、技能、模式、语音、发送等工具分组明确。
3. 输入区上方的引用卡片应轻量，不遮挡主聊天。
4. 发送按钮始终固定在右侧。
5. disabled 时说明原因，例如“当前对话正在输出”。

### 12.4 Card

AgentHub 只在这些场景使用 card：

1. Artifact。
2. 审批。
3. 运行状态。
4. 空态任务建议。
5. Modal 内容。

不要把页面 section、sidebar、chat canvas 全部做成 card。

### 12.5 Tabs

适用于文件、版本、输出、日志。

规范：

1. 高度 36-40px。
2. active tab 使用底线或背景，不只用文字加粗。
3. dirty 状态使用小点或文字，不用强 warning badge。
4. 超过宽度后横向滚动，不换行。

### 12.6 File Tree

规范：

1. 行高 28-32px。
2. 文件图标 14-16px。
3. 缩进每层 14-16px。
4. hover 背景弱于 active。
5. 当前打开文件使用 active 背景 + 细左线。
6. 操作按钮只在 hover 或选中时出现。

### 12.7 Code Editor / Terminal

规范：

1. 使用专用代码背景，不复用普通 panel。
2. 行号、路径、终端输出使用 mono。
3. 代码区圆角不超过 8px。
4. 代码区域边框要弱，避免像卡片。
5. 终端输出区使用更高对比的时间与等级色。

### 12.8 Status Chip

状态 chip 用于运行状态，不用于装饰。

| 状态 | 视觉 |
| --- | --- |
| Running | 绿色/蓝色点 + 文案 |
| Waiting | amber 点 + 文案 |
| Failed | red 点 + 文案 |
| Done | muted success |
| Draft | faint |

规则：

1. chip 高度 20-24px。
2. 状态点 6-8px。
3. 不使用全彩大胶囊堆满界面。

## 13. 交互设计规范

### 13.1 Hover

1. hover 用于提示可点击，不改变布局。
2. hover 背景变化控制在 120ms。
3. 工具按钮 hover 可显示 tooltip。
4. 列表 row hover 不显示过多操作，最多 1-2 个。

### 13.2 Active / Pressed

1. pressed 状态可以轻微 scale 0.98 或背景加深。
2. 不使用弹跳。
3. 对危险动作，pressed 不直接执行破坏性结果，必须二次确认。

### 13.3 Focus

1. 键盘 focus 必须可见。
2. focus ring 使用 brand accent soft。
3. 深色模式 focus 不要只靠边框亮度。

### 13.4 Loading

1. 首屏用 skeleton，而不是只显示“加载中”。
2. 文件树 loading 使用行级 skeleton。
3. 消息 loading 使用消息形 skeleton。
4. 运行 loading 使用状态条和日志渐进，不要让用户猜。

### 13.5 Empty State

AgentHub 的空态必须是“起手动作”，不是“解释页面”。

模板：

```text
身份/上下文
一句话说明
主动作
2-4 个任务建议
```

规则：

1. 空态不超过 80 字。
2. 每个建议必须可点击。
3. 点击后最好写入输入框或打开对应 panel。
4. 不使用插画型空态。

### 13.6 Error State

错误态要告诉用户：

1. 发生了什么。
2. 是否影响当前工作。
3. 可以怎么恢复。

错误视觉不要一律大红。只有破坏性或阻断性错误才用 danger。

## 14. 动画设计规范

### 14.1 动效原则

AgentHub 的动效应该像专业工具：

1. 帮用户理解状态变化。
2. 帮用户定位新内容。
3. 帮用户确认操作结果。
4. 不为了炫技而动。

### 14.2 时间规范

| 动画 | 时长 | 用法 |
| --- | --- | --- |
| hover | 100-140ms | 按钮、列表 |
| active press | 80-120ms | 点击反馈 |
| popover in | 120-160ms | 菜单、tooltip |
| panel slide | 180-240ms | 文件区、侧栏 |
| modal in | 180-220ms | 页面级弹窗 |
| toast | 140-180ms | 通知 |
| skeleton shimmer | 1100-1400ms | 加载 |

### 14.3 缓动

推荐：

| 用途 | easing |
| --- | --- |
| 普通 UI | `ease-out` |
| panel 展开 | `cubic-bezier(0.16, 1, 0.3, 1)` |
| 消失 | `ease-in` |
| hover | `ease` |

### 14.4 禁止项

1. 不做大面积背景动画。
2. 不做随机漂浮光斑。
3. 不做弹簧感很强的工作台动效。
4. 不让消息流因为动画造成阅读跳动。
5. 不使用动效掩盖状态不清晰的问题。

### 14.5 Reduced Motion

所有 panel slide、popover、modal、loading shimmer 都必须有 reduced-motion 降级。降级后保留透明度变化即可。

## 15. 分端视觉规范

### 15.1 SaaS Web / Local Desktop

共享主工作台视觉：

1. 深色优先，浅色同等可用。
2. 三层工作区。
3. 项目和文件感知更强。
4. 高密度工具栏。
5. 文件区接近 IDE。

主题规则：

1. 深色主题用于长时间工程工作、夜间环境、代码和终端密集场景。
2. 浅色主题用于白天办公、投屏、评审、非技术团队协作场景。
3. 深浅主题必须保持同一信息架构和组件尺寸，不允许浅色主题变成另一套布局。
4. 浅色主题的文件区和代码区仍要保持工程感，不能全部漂白成普通文档页。
5. 切换主题时，只允许 token 变化，不允许按钮位置、列表密度、面板层级变化。

差异：

| Surface | 视觉重点 |
| --- | --- |
| SaaS Web | 登录可信度、团队空间感、云端状态 |
| Local Desktop | 本机文件感、CLI 运行感、工程控制感 |

### 15.2 Mobile

移动端不应直接缩放桌面 UI。

建议：

1. 使用底部 tab。
2. 每次只显示一个主任务：会话、文件、审批、通知。
3. 文件预览优先，复杂编辑弱化。
4. 运行状态要有顶部 summary。
5. 操作按钮不小于 44px。

## 16. 与现有 `agenthub-*` token 的关系

当前 `frontend/src/index.css` 已有较完整的 token 基础。后续应将它整理为四类：

| 类别 | 示例 |
| --- | --- |
| Color tokens | `--ah-app-bg`、`--ah-panel-bg`、`--ah-text` |
| Shape tokens | `--ah-card-radius`、`--ah-panel-radius` |
| Motion tokens | 建议新增 duration、easing、reduced-motion 规则 |
| Component tokens | button、list-row、file-tree、composer、modal |

建议命名方向：

```text
--ah-color-bg-app
--ah-color-bg-panel
--ah-color-text-primary
--ah-radius-panel
--ah-radius-control
--ah-duration-fast
--ah-duration-panel
--ah-ease-standard
```

这不是要求立刻改代码，而是后续设计系统整理时的命名方向。

## 17. UI/UX 优化优先级

### P0：先把“像专业产品”的基础打稳

1. 统一圆角、按钮、列表、hover、active。
2. 优化左侧会话列表的 active 态和信息层级。
3. 收紧主工作台面板阴影和卡片感。
4. 文件区向 IDE 化视觉靠拢。
5. 给运行状态建立统一 chip 和状态条。
6. 深色和浅色主题同步验收，不允许只优化深色。

### P1：增强 AgentHub 自己的视觉识别

1. 确定唯一 brand accent。
2. 建立 Agent 头像色板规则。
3. 建立 Project、Agent、Artifact 的图标体系。
4. 将“项目工作台”视觉作为 AgentHub 的核心识别，而不是普通 IM。

### P2：沉淀设计系统

1. 建立 Figma token。
2. 建立组件状态矩阵。
3. 建立 motion spec。
4. 建立跨端规范。
5. 建立设计验收 checklist。

## 18. 设计验收 Checklist

每次 UI 迭代前后，用这份 checklist 审核：

- 当前页面是否一眼能看出所在 Project 和 Session。
- 当前会话、当前文件、当前运行状态是否都有明确位置。
- 同类按钮尺寸是否一致。
- 同类列表行高度是否一致。
- active、hover、selected、unread 是否视觉上可区分。
- 主工作区是否避免卡片套卡片。
- 是否存在无意义大阴影。
- 是否存在泛 AI 紫蓝渐变装饰。
- 空态是否提供下一步动作。
- 错误态是否说明恢复方式。
- loading 是否使用匹配骨架。
- 动效是否在 240ms 内完成。
- reduced-motion 是否可降级。
- 文件区是否像工作区，而不是临时弹窗。
- 代码区是否使用等宽字体和低圆角。
- 移动端是否避免直接压缩桌面布局。
- 浅色主题是否避免大面积纯白和模板化后台感。
- 浅色主题的 active、hover、selected、unread 是否仍然可区分。
- 浅色主题的代码区和终端区是否保持工程工作台质感。
- 深浅主题切换后组件尺寸、布局层级和交互位置是否保持一致。
- 深浅主题中的状态色是否都通过可读性检查。

## 19. 最终设计方向总结

AgentHub 要逼近 Coze、Cursor、VS Code、Codex 这一类专业产品，关键不是增加更多装饰，而是把已有能力用更专业的视觉语言表达出来：

1. 用稳定的三层工作台表达产品架构。
2. 用高密度但清晰的组件表达工程效率。
3. 用统一状态系统表达 AI 运行过程。
4. 用 IDE 化文件区表达 Project-first。
5. 用克制动效表达反馈，不打扰长时间工作。
6. 用唯一 brand accent 建立识别，不依赖 AI 渐变套路。
7. 用深浅双主题 token 保证不同办公环境下都专业、可读、稳定。

最终目标是：用户打开 AgentHub 时，不只是觉得它“好看”，而是立刻相信它可以承载真实项目、真实 Agent、真实文件和真实交付。
