## 2. 执行结论

本次审视后，我的判断很明确：

1. AgentHub 已经具备不错的结构基础，尤其是暗色工作台、项目-会话-Agent 三层组织关系、对话与运行态融合方向是对的。
2. 当前差距主要不在“有没有功能”，而在“首屏落点、任务起手、状态解释、动作层级、专业界面张力”这五件事。
3. 最伤体验的不是大功能缺失，而是几个关键瞬间不够专业：
   - 未登录时像“报错”，不像“正常进入入口”
   - 空白会话没有任务起手动作，主画布价值感偏空
   - 项目文件入口不够显性，工作台语义还不够像一个工程生产环境
   - 桌面 Web 在窄视口下有轻微拥挤感
4. 这类问题适合先做一轮不改信息架构的大幅提纯，再进入第二阶段的系统级工作台升级。

基于这个判断，我已经先完成了一批前端快修，并把后续方案拆成可执行路线图。

## 3. 调研方法与范围说明

### 3.1 真实体验范围

本次不是只看代码，而是结合了真实线上页面体验：

- 已部署 Web 端：`http://120.26.47.229/`
- 未登录态体验
- 注册并进入真实工作台后的空白会话体验
- 窄视口/移动视口下的页面表现
- 本地前端代码结构与壳层差异

### 3.2 代码层事实

结合前端壳层代码，当前产品前端结构可以归纳为：

1. `SaaS Web` 走 `AuthGate -> AgentHubWorkbench`
2. `Local Desktop` 直接走 `AgentHubWorkbench`
3. `Mobile` 是独立 `MobileShell`

这意味着：

- Web 登录体验属于 SaaS 专属问题
- 大部分桌面工作台优化可同时收益 Web 与 Desktop
- 移动端需要单独策略，不能直接拿桌面布局硬缩放

## 4. 对标产品结论

本轮参考了官方公开页面与文档，提炼的不是表层视觉，而是这些成熟产品背后的界面原则。

### 4.1 VS Code：稳定骨架与上下文保持

VS Code 官方文档强调的是稳定的工作台骨架：Explorer、Editor、Side Bar、Status Bar、Panel 各司其职，并且会保留用户上次关闭时的布局、文件和上下文状态。对 AgentHub 的启发是：

1. 主工作台必须让用户始终知道“我在哪、我能做什么、下一步去哪”
2. 项目上下文、文件入口、运行状态不应藏在次级路径里
3. 空白状态不能只是留白，而应该是有上下文的工作准备区

来源：

- VS Code User Interface: https://code.visualstudio.com/docs/editing/userinterface

### 4.2 Codex：异步委派与可验证执行

Codex 官方介绍强调两点：

1. 一个工程代理可以并行处理多个任务
2. 用户必须能通过日志、测试结果、引用等方式验证代理做了什么

对 AgentHub 的启发是：

1. 主会话不是普通聊天窗口，而应是“任务控制台”
2. 起手动作要更任务化，而不是只给一个输入框
3. 运行态与结果态要更加可解释，避免用户怀疑系统“是不是没在干活”

来源：

- Introducing Codex: https://openai.com/index/introducing-codex/

### 4.3 Cursor：把“开始工作”变成最低阻力动作

Cursor 官方页面持续强化几件事：

1. 把任务直接交给 Agent，用户专注判断与决策
2. `Tab / Agent / CLI` 各自语义清楚
3. `/ commands`、`@ files`、`! shell` 这类高频入口非常直接

对 AgentHub 的启发是：

1. 会话空态需要明确的任务模板和行动建议
2. 文件上下文与输入框应一跳可达
3. AI 工作区不应让用户先“想怎么开口”，而应帮用户更快起手

来源：

- Cursor official site: https://cursor.com/en-US

### 4.4 扣子 Coze：低门槛起手与清晰的 AI 工作台表达

这里的 Coze 特指字节的扣子，而不是海外泛 Agent 站点。扣子官方页面强调“AI 办公助手一站式平台”和“AI Agent 智能办公平台”，它对 AgentHub 的 UI/UX 启发更直接：

1. 首屏要让用户更快知道“现在可以做什么”，而不是只进入空白会话
2. Agent、Project、Files、Runs、Artifacts 这些已有对象，需要在界面层形成更连续的工作感
3. 空态、快捷动作、示例任务要更具体，让用户不用先组织复杂提示词
4. AgentHub 的工程优势应通过视觉层级更早暴露，例如项目上下文、文件入口、运行状态和产物入口
5. 对新用户要减少概念解释，增加可点击、可预填、可继续编辑的任务模板

来源：

- 扣子官网/推广页：https://www.coze.cn/overview/promotion
- 扣子官网：https://www.coze.cn/
- 扣子文档：https://www.coze.cn/docs

### 4.5 飞书/Lark：减少上下文切换，统一工作入口

Lark 官方表达非常清楚：Chat、Docs、Meetings、Projects 在一个地方完成，减少团队在多个工具之间来回切换。对 AgentHub 的启发是：

1. Project、Session、Files、Artifacts 之间的切换成本还可以继续压低
2. 每一个主要界面都应该像“工作入口”，而不是“功能列表”
3. 界面应该强化连贯性，而不是让用户自己拼工作流

来源：

- Lark official site: https://www.larksuite.com/en_sg/

## 5. 当前体验诊断

### 5.1 登录态入口：当前更像异常反馈，不像正常入口

线上 Web 未登录时，页面会先出现“正在检查登录态”，稍后进入登录卡片。原先的核心问题有两个：

1. 401/未登录会被当成红色错误展示，心理感受偏“被拦截”
2. 加载态文案过短，用户不清楚系统是在恢复登录、检查状态，还是卡住了

这会降低首屏专业感，也会让首次访问者误判系统稳定性。

### 5.2 会话空态：视觉干净，但任务起手成本偏高

已登录后的空白会话，主区只显示“开始对话吧”。这在一般 IM 场景没问题，但放在工程型 AI 工作台里不够强：

1. 没有给出任务模版
2. 没有强调当前 Agent 身份与适合处理什么
3. 没有把 Project 文件、审查、规划、实现这些高频动作前置

结果是界面虽然简洁，但第一步缺少抓手。

### 5.3 Project 文件入口不够前台化

AgentHub 的核心竞争力之一不是聊天本身，而是 Project-first 的工程工作区。但从当前桌面会话头部看，文件资源管理器入口还不够像一级生产力工具。和 VS Code / Cursor 一类产品相比，这会削弱“工程控制台”的感知。

### 5.4 视觉气质已经有方向，但还可以更收、更利落

当前界面整体方向是对的：深色、低饱和、弱装饰、信息密度偏高。但部分细节仍略软：

1. 卡片与阴影稍厚
2. 某些状态块与引用块层次不够精炼
3. 空态区域视觉支撑偏弱，导致主画布显空

### 5.5 窄视口桌面 Web 有轻微拥挤

从移动尺寸截图看，桌面 Web 壳在窄屏下会出现纵向堆叠和操作区压缩感。虽然真实移动端有独立壳，但这仍说明桌面 Web 的窄视口适配有继续提升空间。

## 6. 本轮已完成优化

这次我先落了一批不破坏整体架构、但能显著提升第一感受与起手效率的改动。

### 6.1 登录体验优化

已完成：

1. 将“未登录 / 401”从红色全局错误中剥离，改为正常进入登录入口
2. 区分“正在恢复登录态”和“正在检查登录态”
3. 为登录卡片增加辅助说明文案
4. 优化卡片宽度、圆角与主按钮气质
5. 给表单字段补齐 placeholder，降低首次填写阻力

预期效果：

- 让登录过程更像专业 SaaS 入口
- 减少“系统报错了”的误判
- 提升第一次使用时的情绪稳定感

### 6.2 空白会话升级为任务起手面板

已完成：

1. 将单句空态替换为带 Agent 身份信息的任务起手面板
2. 增加主按钮“立即开始”
3. 当会话绑定 Project 时，增加“打开项目文件”
4. 为单 Agent 与群聊分别提供四组更贴近真实工作的建议动作

单 Agent 任务建议包含：

- 审查当前项目
- 定位一个问题
- 设计实现方案
- 开始写代码

群聊任务建议包含：

- 先拆解任务
- 安排多人协作
- 审查当前项目
- 整理交付方案

预期效果：

- 降低起手负担
- 强化 AgentHub 是“做事”而不是“闲聊”
- 更接近 Cursor / Codex 这类任务型 AI 界面

### 6.3 输入框支持一键预填充

已完成：

1. 新增 `agenthub:prefill-chat-input` 事件
2. 推荐动作卡片点击后可自动写入输入框
3. 自动聚焦输入框并把光标放到末尾

这件事虽然小，但它是从“建议”到“立即开始做”的关键链路。

### 6.4 Project 文件入口前置

已完成：

1. 在会话头部加入项目资源管理器入口按钮
2. 保持它位于会话文件入口之前
3. 没有关联 Project 时禁用，并给出明确提示

预期效果：

- 强化 Project-first 工作区语义
- 缩短“聊天 -> 文件 -> 修改 -> 回到聊天”的路径

### 6.5 视觉 token 微调

已完成：

1. 收紧全局卡片圆角
2. 降低阴影厚重感
3. 新增认证卡片、空态面板、建议卡片、代码引用块的样式层级

预期效果：

- 整体更利落、更像专业工具
- 保留现有视觉语言，不做风格跳变

## 7. 推荐的下一阶段 UI/UX 方案

下面是我建议继续推进的界面体验路线。优先级从高到低排列，均限定在前端 UI/UX 与交互表达层，不代表新增产品能力范围。

### 7.1 P0：把工作台首屏打磨到专业级

#### P0.1 登录态首屏完整化

目标：把 SaaS 进入流程做成“可信入口”。

建议：

1. 为登录检查增加超时兜底文案
2. 在登录卡片底部加入空间说明，例如“进入个人空间 / 团队空间”
3. 对注册模式增加更明确的收益型文案，而不是只显示字段
4. 为认证过程补上轻量 skeleton，而不是纯文本等待

#### P0.2 空态全链路任务化

目标：让每个空会话都能 3 秒内开工。

建议：

1. 按会话类型区分空态
2. 按 Agent 能力自动生成建议动作
3. 对历史使用频率高的动作做置顶
4. 支持二次点击“追加到输入框”而不是只能替换

#### P0.3 强化 Project 工作区感

目标：让 AgentHub 从“聊天产品”进一步靠近“工程工作台”。

建议：

1. 顶部栏增加更明确的 Project 上下文
2. 文件入口与会话文件入口语义区分更清楚
3. 记忆上次文件工作区展开状态
4. 让 Project、Session、Files 三者形成更稳定的视觉主线

### 7.2 P1：重构运行态与协作态的界面表达

建议 2-4 周完成。

#### P1.1 让聊天流更像可理解的任务控制界面

建议：

1. 用更清晰的视觉状态区分排队、执行中、等待输入、等待审批、完成
2. 在会话头部用轻量摘要呈现当前运行状态
3. 将多 Agent 协作的关键节点以更清晰的 UI 层级呈现，不要完全沉到消息流中

#### P1.2 让 Artifact / Files / Message 的入口关系更清楚

建议：

1. 主会话头部保留更清晰的最新变更或最新产物入口
2. Artifact 和 Project Files 的按钮、标签、文案要让用户一眼区分语义
3. 重要产物在会话中使用更明确的优先级视觉

#### P1.3 为窄屏桌面 Web 做专门排版

建议：

1. 在小于某个宽度时主动切换为更明确的双段式布局
2. 压缩非核心工具位，保留输入、搜索、文件、运行信息四个高频要素
3. 避免主操作区和头部操作区同时过密

### 7.3 P2：建立长期设计系统能力

#### P2.1 形成 AgentHub 自己的生产力设计系统

建议：

1. 固化工作台组件层级、密度、留白、圆角、阴影、状态色规则
2. 为空态、运行态、异常态、成功态建立统一组件语言
3. 形成桌面 Web / Local Desktop / Mobile 三端共通 token 与差异化规范

#### P2.2 补齐数据化 UX 评估

建议重点埋点：

1. 首次进入登录页到完成登录的转化率
2. 空白会话从进入到首条消息发送的时间
3. 推荐动作卡片点击率
4. 文件入口使用率
5. 会话中断后恢复执行的成功率

## 8. 设计原则建议

后续所有前端迭代，建议统一遵守以下原则。

### 8.1 默认展示“下一步”

不要只展示容器，要展示下一步动作。

### 8.2 对高频工程用户，信息密度可以高，但层级必须非常清楚

不是减少信息，而是减少犹豫。

### 8.3 AI 产品要减少“解释我是谁”，增加“我现在能替你做什么”

这也是 Codex、Cursor、Coze 这类产品共同在做的事。

### 8.4 首屏避免把正常状态误表现成异常

登录、恢复、同步、运行中，都不应轻易长得像报错。

### 8.5 文件、任务、对话必须是一个连续工作流

不要让用户自己在三个区块之间补脑。

## 12. 最终建议

如果你们希望产品在感知上更接近 Coze、VS Code、Codex、Cursor、飞书这一档，我建议不要一上来大改框架，而是沿着下面这条路线走：

1. 先把首屏、空态、起手动作、文件入口做到“专业工具该有的样子”
2. 再把运行态、协作态、Artifact/Files/Message 的界面关系讲清楚
3. 最后沉淀设计系统、体验埋点和跨端一致性

AgentHub 现在距离“好用”已经不远，下一步需要的是把它从“功能成立”推到“工作起来有压迫感地顺手”。
