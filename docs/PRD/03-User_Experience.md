# 需求规格说明书 (PRD)：03 - 交互体验与界面原型设计 (User Experience & UI Wireframes)

## 1. 文档定位
本文档专为**UI/UX 设计师**以及**前端开发工程师**编写。
为了方便直接将其内容输入给 UI 原型生成 AI（如 Midjourney、v0.dev 或 Figma AI），本节将使用高度画面感、结构化的语言，精确描述每一个核心界面的空间布局、元素排列以及动态交互逻辑。本系统无需关注过于具体的颜色和圆角，只需保证排版的科学性与生产力属性。

---

## 2. 宏观全局布局：动态三栏式 (The Dynamic 3-Column Layout)

整个 AgentHub 的界面基于浏览器全屏（Desktop-first）设计。系统在水平方向上被严格划分为三个区域。

### 2.1 区域划分定义
*   **左区 (Sidebar - 会话与资产库)**：宽度固定（约 260px）。背景色略深于主屏。
*   **中区 (Main Chat - 主战场)**：自适应宽度（`flex: 1`）。是用户与 AI 团队沟通的核心信息流。
*   **右区 (Artifact Drawer - 产物抽屉)**：宽度动态变化。平时宽度为 `0`（完全隐藏）。一旦滑出，宽度占据总屏幕的 `40% - 50%`。支持鼠标拖拽左侧边缘调整宽度。

## 3. 核心界面原型详述 (Wireframe Descriptions)

### 3.1 界面一：空状态首屏 (The Empty State & Onboarding)
**【场景描述】**：用户第一次打开系统，或者在左侧点击了“新建会话”后的默认状态。
**【视觉布局】**：
*   **左侧导航栏**：
    *   顶部是两个并排的 Tab 按键：`[💬 聊天]` 和 `[🤖 专家库]`，当前高亮“聊天”。
    *   下方是一个列表，包含一个醒目的按钮 `[+ 新建协作任务]`。
    *   列表底部角落有一个带警告图标的**【环境体检卡片】**，绿字显示“Claude Code 已就绪”，红字显示“Docker 未启动”。
*   **中央区域**：
    *   极其干净，大面积留白。屏幕**正中央**水平垂直居中放置着一个巨大的输入框（高度可随文字自动撑开）。
    *   输入框上方有一句问候语，由 Orchestrator 大管家头像发出：“你好！我是你的 AI 项目经理，今天想开发什么产品？”。
    *   输入框下方并排悬浮着 3 个胶囊状的快捷指令推荐（Prompt Pills），如 `[✨ 设计一个登录页]`、`[📊 爬取最新 AI 论文]`。
*   **右侧区域**：无，完全收起。

### 3.2 界面二：意图输入与聊天流态 (The Chat Stream)
**【场景描述】**：用户在中央输入框敲下回车后，中央界面的形态瞬间转变。
**【视觉布局】**：
*   **中央大框下沉**：原本居中的巨大输入框平滑动画下落，吸附到屏幕最底部，并缩减为一个常规高度的聊天栏。
*   **消息瀑布流**：中间区域从下往上开始涌现聊天气泡。
    *   用户的发言在右侧（深色气泡）。
    *   系统（Agent）的发言在左侧（浅色气泡）。
*   **Orchestrator 调度展示**：
    *   此时系统不会立刻回答，而是由大管家头像吐出一个叫做**“DAG 任务看板”**的特殊卡片。
    *   卡片内部是一个横向滚动的流程图。包含 3 个方块，箭头连接：`[需求澄清 (Pending)] -> [接口设计 (Pending)] -> [代码开发 (Pending)]`。
    *   第一个方块亮起黄灯（表示 RUNNING）。

### 3.3 界面三：群聊氛围与资产卡片 (The Asset Card)
**【场景描述】**：第一个子任务完成，底层的前端 Agent 产出了几百行的代码，并交回给用户。
**【视觉布局】**：
*   **多 Agent 登场**：聊天流的左侧，头像不再是 Orchestrator。而是出现了一个戴着眼镜的卡通头像，名字标注为 `前端架构师 Agent`。
*   **告别代码刷屏**：这个前端 Agent 说话的气泡里，**绝对没有一整坨黑色的 Markdown 代码块**。它只有一句话：“页面框架已搭建完毕，请查收成果。”
*   **资产卡片 (Asset Card)**：紧接着这句话，气泡下方悬挂着一张精美的圆角白色卡片。
    *   卡片左边是一个图标（如 `🌐 Web` 或 `📝 Doc`）。
    *   卡片中间是加粗标题：“图书管理首页_v1.0”。
    *   卡片右侧有两个按钮：`[👀 预览产物]` 和 `[💬 引用此版本]`。

### 3.4 界面四：三栏全开与所见即所得 (The 3-Column Drawer)
**【场景描述】**：用户点击了刚才那张资产卡片上的 `[👀 预览产物]` 按钮。
**【视觉布局】**：
*   **抽屉滑出**：整个中间聊天流向左被挤压，右侧平滑地滑出一个占据屏幕一半的抽屉（Drawer）。
*   **抽屉内部布局（代码/预览双态）**：
    *   **顶部工具栏**：抽屉最上方有两个 Toggle 按钮：`[代码 Diff]` 和 `[网页预览]`。
    *   如果选了 `[代码 Diff]`，下方展示类似 VS Code 的并排对比试图，左红右绿，左侧还有一排细细的文件树列表。
    *   如果选了 `[网页预览]`，下方是一个巨大的带白底边框的 IFrame 容器，里面真实渲染了刚才那个登录页的视觉效果。
*   **跨屏互动**：此时用户目光盯着右半屏的网页预览，发现按钮颜色不对。他的手不需要离开键盘，直接在中间底部（吸底的）输入框打字：“把右边那个按钮改成红色”。按下回车。

### 3.5 界面五：人机握手与断点审批 (Human-in-the-loop)
**【场景描述】**：后台架构师 Agent 写完了一份核心的数据库表结构 PRD。根据 Orchestrator 的规则，此时必须人工介入，否则流水线暂停。
**【视觉布局】**：
*   在中间聊天流的最底部，出现一条具有**强阻断感**的特殊消息（四周带有红色或橙色的发光边框警戒线）。
*   文字提示：“⚠️ 架构设计已完成。请审批右侧产物后，再决定是否进入后续开发阶段。”
*   消息正下方并排两个巨大的按钮：
    *   **绿色实心按钮**：`[✅ 确认无误，启动下阶段]`。
    *   **红色描边按钮**：`[❌ 驳回，需重新修改]`。
*   在用户没有点击这两个按钮之前，整个聊天流的输入框会被加盖一个半透明的 `[流水线已暂停]` 的遮罩（但允许用户通过特定的 `@` 继续与架构师就这份产物展开辩论）。

## 4. 关键交互微动效设计 (Micro-interactions)
为增强产品的专业感与“活生生”的 Agent 感，前端需实现以下微动效：
1.  **打字机流推 (SSE Typewriter)**：当 Agent 输出文字时，最后一个字必须带有一个闪烁的光标（`|`），且滚动条必须自动且平滑地锚定在最底部。
2.  **卡片呼吸灯**：当某个底层 CLI 进程处于 `RUNNING` 状态时，其对应的头像或任务卡片边缘需有微弱的呼吸灯扫描效果，暗示“我在玩命算”，缓解用户的等待焦虑。
3.  **引用锚点跳转**：当用户点击一张历史资产卡片上的 `[💬 引用此版本]` 时，底部的输入框上方会出现一个悬浮的引用标签。点击这个标签，聊天流会极其平滑地高亮并滚动追溯到历史的那个位置。
