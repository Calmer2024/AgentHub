# 需求规格说明书 (PRD)：03 - 交互体验与界面原型设计 (User Experience & UI Wireframes)

## 1. 文档定位
本文档专为**UI/UX 设计师**以及**前端开发工程师**编写。
为了方便直接将其内容输入给 UI 原型生成 AI（如 Midjourney、v0.dev 或 Figma AI），本节将使用高度画面感、结构化的语言，精确描述每一个核心界面的空间布局、元素排列以及动态交互逻辑。本系统无需关注过于具体的颜色和圆角，只需保证排版的科学性与生产力属性。

## 2. 宏观全局布局：Project-first 三栏式

整个 AgentHub 的界面基于浏览器全屏（Desktop-first）设计。系统在水平方向上被严格划分为三个区域。

### 2.1 区域划分定义
*   **左区 (Project Sidebar)**：宽度固定（约 240-260px）。参考 Codex 客户端和飞书/Telegram 的侧栏语义，承载快速入口、好友/设置入口、Project 列表和创建 Project 菜单。
*   **中区 (Session List)**：宽度固定（约 280-320px）。只展示当前 Project 下的私聊/群聊会话，支持新建聊天、搜索、置顶、归档箱、未读数、免打扰、重命名、删除和摘要。
*   **右区 (Chat View)**：自适应宽度（`flex: 1`）。是用户与 AI 团队沟通的核心信息流，底部固定输入框。
*   **Artifact Overlay（页面级展开层）**：Artifact Card、会话文件入口、审批卡片均打开页面级弹窗，用于预览、Diff、版本切换和局部编辑；不恢复 P1 右侧 Drawer。

### 2.2 Project 创建入口

Project 是进入聊天前的第一层上下文。用户在左侧 Project 区点击创建按钮时，不出现复杂表单，而是弹出一个小菜单：

```text
新建空白文件夹
选择现有文件夹
```

*   **新建空白文件夹**：后端在 `AGENTHUB_WORKSPACE_ROOT` 下创建目录并写入 `.agenthub/project.json`。
*   **选择现有文件夹**：本机后端调用系统原生目录选择器，返回一次性 `folderToken` 后创建 Project。
*   **不显示项目类型**：不提供“静态网页 / Vite React / 已有项目”等选择项；预览与构建能力由后端根据文件结构判断。

## 3. 核心界面原型详述 (Wireframe Descriptions)

### 3.1 界面一：空状态首屏 (The Empty State & Onboarding)
**【场景描述】**：用户第一次打开系统，尚未创建 Project；或当前 Project 下还没有会话。
**【视觉布局】**：
*   **左侧导航栏**：
    *   顶部是 Codex 风格的快速入口：快速对话、搜索、插件、自动化、移动版。
    *   中部是 Project 区。无 Project 时显示“暂无项目”，右上角创建按钮可打开两项菜单。
    *   底部是 Agent/设置入口，后续环境体检可在这里进入。
*   **中间会话列表栏**：
    *   无 Project 时提示“创建 Project 后开始”。
    *   有 Project 但无会话时提示“在当前项目中新建私聊或群聊”。
*   **右侧聊天区**：
    *   无会话时保持安静空态，不展示营销式欢迎页。
    *   有会话后显示消息流和底部输入框。

### 3.2 界面二：意图输入与聊天流态 (The Chat Stream)
**【场景描述】**：用户在中央输入框敲下回车后，中央界面的形态瞬间转变。
**【视觉布局】**：
*   **中央大框下沉**：原本居中的巨大输入框平滑动画下落，吸附到屏幕最底部，并缩减为一个常规高度的聊天栏。
*   **消息瀑布流**：中间区域从下往上开始涌现聊天气泡。
    *   用户的发言在右侧（深色气泡）。
    *   系统（Agent）的发言在左侧（浅色气泡）。
*   **Orchestrator 调度展示**：
    *   此时系统不会立刻回答，而是由大管家头像吐出一个叫做**“DAG 任务看板”**的特殊卡片。
    *   卡片内部是一个横向滚动的流程图。包含 3 个方块，箭头连接：`[需求澄清 (Pending)] -> [接口设计 (Pending)] -> [代码开发 (Pending)]`。
    *   第一个方块亮起黄灯（表示 RUNNING）。

### 3.3 界面三：群聊氛围与资产卡片 (The Asset Card)
**【场景描述】**：第一个子任务完成，底层的前端 Agent 产出了几百行的代码，并交回给用户。
**【视觉布局】**：
*   **多 Agent 登场**：聊天流的左侧，头像不再是 Orchestrator。而是出现了一个戴着眼镜的卡通头像，名字标注为 `前端架构师 Agent`。
*   **告别代码刷屏**：这个前端 Agent 说话的气泡里，**绝对没有一整坨黑色的 Markdown 代码块**。它只有一句话：“页面框架已搭建完毕，请查收成果。”
*   **资产卡片 (Asset Card)**：紧接着这句话，气泡下方悬挂着一张精美的圆角白色卡片。
    *   卡片左边是一个图标（如 `🌐 Web` 或 `📝 Doc`）。
    *   卡片中间是加粗标题：“图书管理首页_v1.0”。
    *   卡片右侧有两个按钮：`[👀 预览产物]` 和 `[💬 引用此版本]`。
*   **卡片出现规则**：资产卡片必须由标准 `artifact.created` 事件驱动，不允许前端仅靠扫描 Markdown 临时渲染。每张卡片绑定 `artifact_id`、`version`、`message_id`、`task_id`，保证后续预览、引用、编辑、审批都能追溯。
*   **卡片入口统一**：同一个 Artifact 可以从聊天流卡片、会话文件入口、审批卡片三个入口打开，打开后的页面级弹窗状态一致。

### 3.4 界面四：页面级产物预览与所见即所得 (Artifact Overlay)
**【场景描述】**：用户点击了刚才那张资产卡片上的 `[👀 预览产物]` 按钮。
**【视觉布局】**：
*   **页面级弹窗打开**：聊天流保持上下文位置不漂移，中央打开可关闭的页面级预览/编辑弹窗。
*   **弹窗内部布局（代码/预览双态）**：
    *   **顶部工具栏**：弹窗最上方有两个 Toggle 按钮：`[代码 Diff]` 和 `[网页预览]`。
    *   如果选了 `[代码 Diff]`，下方展示类似 VS Code 的并排对比试图，左红右绿，左侧还有一排细细的文件树列表。
    *   如果选了 `[网页预览]`，下方是一个巨大的带白底边框的 IFrame 容器，里面真实渲染了刚才那个登录页的视觉效果。
*   **回到聊天继续修改**：用户发现按钮颜色不对后，可在弹窗里引用产物/代码片段，回到聊天输入框发送“把按钮改成红色”。消息携带 `referenced_artifact_id` 和 `referenced_version`。
*   **局部编辑入口**：在代码/Diff 模式中选中一段代码后，弹窗内出现紧凑编辑条，包含修改意图输入框、生成 Diff、确认、拒绝。确认后聊天流追加一张新版本卡片，版本管理弹窗切到新版本。

### 3.5 界面五：人机握手与断点审批 (Human-in-the-loop)
**【场景描述】**：后台架构师 Agent 写完了一份核心的数据库表结构 PRD。根据 Orchestrator 的规则，此时必须人工介入，否则流水线暂停。
**【视觉布局】**：
*   在中间聊天流的最底部，出现一条具有**强阻断感**的特殊消息（四周带有红色或橙色的发光边框警戒线）。
*   文字提示：“架构设计已完成。请审阅关联产物后，再决定是否进入后续开发阶段。”
*   消息正下方并排两个巨大的按钮：
    *   **绿色实心按钮**：`[✅ 确认无误，启动下阶段]`。
    *   **红色描边按钮**：`[❌ 驳回，需重新修改]`。
*   在用户没有点击这两个按钮之前，整个聊天流的输入框会被加盖一个半透明的 `[流水线已暂停]` 的遮罩（但允许用户通过特定的 `@` 继续与架构师就这份产物展开辩论）。
*   审批卡片必须显示或链接当前待审阅 Artifact。用户不需要在会话历史中寻找产物；点击卡片的主区域即可打开页面级 Artifact 预览/版本管理弹窗。

## 4. 端到端交互入口清单

| 入口 | 用户动作 | 系统结果 |
|---|---|---|
| Project 创建按钮 | 点击并选择“新建空白文件夹” | 后端创建 Project workspace 并自动选中 |
| Project 创建按钮 | 点击并选择“选择现有文件夹” | 打开系统目录选择器，授权后创建 Project |
| 会话列表新建聊天 | 在当前 Project 下选择私聊或群聊 | 创建归属当前 Project 的 Session |
| 聊天输入框 | 输入完整需求 | 创建会话消息，触发 Orchestrator 或单 Agent |
| 聊天流 Artifact Card | 点击预览 | 打开页面级 Artifact 弹窗并加载指定版本 |
| 聊天流 Artifact Card | 点击引用此版本 | 输入框上方出现引用标签，下一条消息携带 Artifact 引用 |
| Artifact 弹窗代码区域 | 选中代码并输入修改意图 | 调用 Artifact 编辑流程，先展示 Diff 预览 |
| Approval Card | 点击确认 | 任务进入 COMPLETED，下游任务继续 |
| Approval Card | 点击驳回 | 输入框进入针对该任务/Artifact 的修订上下文 |
| 环境体检卡片 | 点击异常项 | 展示缺失 CLI/API Key/运行时的修复提示 |

## 5. 关键交互微动效设计 (Micro-interactions)
为增强产品的专业感与“活生生”的 Agent 感，前端需实现以下微动效：
1.  **打字机流推 (SSE Typewriter)**：当 Agent 输出文字时，最后一个字必须带有一个闪烁的光标（`|`），且滚动条必须自动且平滑地锚定在最底部。
2.  **卡片呼吸灯**：当某个底层 CLI 进程处于 `RUNNING` 状态时，其对应的头像或任务卡片边缘需有微弱的呼吸灯扫描效果，暗示“我在玩命算”，缓解用户的等待焦虑。
3.  **引用锚点跳转**：当用户点击一张历史资产卡片上的 `[💬 引用此版本]` 时，底部的输入框上方会出现一个悬浮的引用标签。点击这个标签，聊天流会极其平滑地高亮并滚动追溯到历史的那个位置。
