# UI/UX设计标准

> 本文档是 AgentHub 当前界面与交互体验的权威设计标准。它约束桌面端主界面、智能体配置、聊天、项目、浮层与反馈组件，并随产品迭代持续更新。

## 1. 文档定位

- 目标：让新增页面和组件保持同一种视觉语言，避免局部优化相互覆盖。
- 读者：产品、设计、前端开发、测试人员和参与界面修改的 Agent。
- 适用范围：桌面端优先，同时为 SaaS Web 和移动端提供可复用原则。
- 更新时机：修改全局色彩、圆角、间距、阴影、交互状态、聊天呈现或导航结构时同步更新。
- 冲突处理：产品范围以 PRD 为准，UX 验收以 `docs/testing/UX_TEST_SPEC.md` 为准，视觉和组件规则以本文档为准。

## 2. 设计方向

AgentHub 采用深色、克制、沉浸式的桌面 IM 设计语言。界面通过背景层级、留白和文字灰度建立结构，不依赖大量边框、发光或套娃卡片。

设计参数：

| 参数 | 目标 | 说明 |
| --- | --- | --- |
| 设计变化度 | 5/10 | 保持结构稳定，在重要页面使用适度非对称布局 |
| 动效强度 | 2/10 | 只保留必要的状态反馈和内容入场，不使用位移动画 |
| 信息密度 | 6/10 | 适合高频桌面工具，紧凑但不拥挤 |

核心原则：

1. 沉浸式无边界：标题栏、侧边栏和应用画布使用统一色彩，避免物理分隔线。
2. 实心状态：hover、focus 和 selected 主要使用实心背景色，不使用外发光。
3. 内容优先：最终回答是聊天主视图第一视觉中心，执行过程和元数据主动降权。
4. 最多两层容器：同一区域不超过两层带背景容器。
5. 稳定交互：hover、click 和 focus 不改变组件位置或尺寸。
6. 可演进：所有新规则优先沉淀为语义类或设计令牌，并同步补充测试。

## 3. 色彩系统

### 3.1 基础背景

- 应用标题栏、智能体配置页标题栏和侧边导航：`#171716`。
- 应用画布使用接近标题栏的暖中性深色，不使用纯黑。
- 输入区、菜单和卡片使用不透明实心背景，避免内容穿透。
- 一个页面只使用一套中性色和一个品牌强调色。

### 3.2 文字层级

| 层级 | 用途 |
| --- | --- |
| 强文本 | 页面标题、消息正文中的关键内容、主要操作 |
| 正文 | 普通消息、表单值、菜单标签 |
| 弱文本 | 辅助说明、备注、时间戳 |
| 极弱文本 | 占位符、禁用状态、非关键元数据 |

正文避免高对比纯白。标题和正文通过字号、字重、间距和灰度建立层级，只对真正关键的信息加粗。

## 4. 排版

- 聊天正文：14-15px，行高 1.6-1.7。
- 内容标题：16-18px，字重 600。
- 菜单与表单：13-14px，保持单行可扫读。
- 连续内容中避免多个大标题和连续粗体。
- 长文本宽度应受控，代码、日志和命令使用等宽字体。
- 中文、英文、数字混排时保证基线一致，不用装饰性全大写标签制造层级。

## 5. 间距与布局

### 5.1 间距基线

使用 4px 基准网格。常用间距为 4、8、12、16、24 和 32px。

- 菜单项之间：4px，形成非连续性悬浮态。
- 图标与文字：8-12px。
- 表单标签与输入控件：8px。
- 内容分组：16-24px。
- 页面章节：32px 起，根据信息密度调整。

### 5.2 表单布局

- 名称与备注上下排列。
- 系统提示词与行为规则上下排列。
- 能力配置与启动命令上下排列。
- 只有短字段、强关联字段且横向空间充分时才使用左右布局。
- 输入框默认无 border，通过实心背景和间距表达边界。

## 6. 圆角与形状

采用分级软圆角系统：

| 组件 | 建议圆角 |
| --- | --- |
| 主视图与配置主面板 | 24-32px，大半径平滑圆角 |
| 弹窗与浮层 | 16-20px |
| 输入框与普通卡片 | 10-16px |
| 聊天气泡 | 10-14px |
| 圆形图标按钮、头像 | 50% |

同一组件在不同状态下不得改变圆角。卡片圆角不能代替信息层级。

## 7. 阴影与层级

- 普通组件不使用阴影。
- 下拉菜单、右键菜单和弹窗可以使用阴影表达浮层关系。
- 菜单标准阴影：`0 10px 24px rgb(0 0 0 / 0.30)`。
- 阴影必须紧凑，不制造大面积雾化轮廓。
- 禁止按钮、输入框和选中状态使用外发光。
- 模态弹窗只使用透明黑遮罩，不使用 backdrop blur。

## 8. 交互状态

### 8.1 Hover

- 使用实心背景色，无 border。
- 不允许 translate、scale、抖动或磁吸位移。
- 列表项之间保留纵向间距，使圆角 hover 框独立呈现。
- 图标尺寸、文字位置和容器尺寸保持稳定。

### 8.2 Click、Active 与 Focus

- 点击后不显示 outline、ring、外发光、drop-shadow 或扩散阴影。
- active 不改变元素位置和缩放比例。
- 键盘 focus-visible 使用实心背景或清晰的内部对比状态，不使用外发光。
- 焦点状态不能造成布局变化。

### 8.3 Selected

- 使用比 hover 更稳定的实心背景。
- 必要时允许一条内部强调线，但不能同时叠加边框、阴影和发光。

### 8.4 Disabled

- 降低文字和图标透明度，保留组件原有布局。
- 不通过模糊表达禁用。
- 鼠标样式应明确不可操作。

## 9. 导航与列表

- 左侧主导航每一项必须使用同一图标家族，图标视觉尺寸统一。
- 设置按钮替代桌面端用户按钮，颜色与其他导航图标一致。
- 好友列表和聊天列表的更多按钮始终位于行尾垂直中心。
- 同一列表项只渲染一个更多按钮，默认低权重，hover 或 focus-within 时出现。
- 好友名称下展示备注，不展示底层 CLI 名称。
- 项目可以展开或收缩其对话，层级通过缩进和间距表达。
- 项目新建对话必须先选择 Agent。

## 10. 菜单与浮层

- 所有下拉菜单、右键菜单和更多菜单统一使用 `.agenthub-menu` 语义表面。
- 背景必须不透明，无 border，使用标准紧凑阴影。
- 菜单项之间保持 4px 间距。
- 菜单项 hover 使用独立圆角实心背景。
- 菜单宽度由内容和任务决定，避免过宽空白或标签换行。
- 危险操作只改变文字或实心背景色，不使用发光警示。

## 11. 聊天主视图

### 11.1 消息

- 用户消息不显示用户头像和用户名称。
- 时间戳默认隐藏，仅在消息 hover 或 focus-within 时显示。
- 消息气泡不使用 border，圆角控制在 10-14px。
- Markdown 正文为 14-15px，行高 1.6-1.7。
- 代码块、文件、执行摘要和可交互产物可以使用卡片，普通文本不套卡片。

### 11.2 执行过程

- 默认折叠为单行状态摘要，并与最终回答气泡分离。
- 摘要只显示状态、步骤数、工具调用次数和耗时。
- 完整步骤、原始命令和日志进入展开面板。
- 执行过程的字号、对比度和空间权重均低于最终回答。

### 11.3 产物

- Agent 生成的每个产物作为一条独立文件消息发送。
- 文件消息展示文件名、类型、大小和主要操作。
- 不把多个无关产物压缩到同一条装饰性卡片中。

### 11.4 输入框

- 使用宽幅纵向布局，文本区在上，附件与发送操作在底部。
- 桌面端初始最小高度为 148px，文本编辑区最小高度为 72px。
- 输入框无 border，不使用 focus 外发光。
- 内容增长到最大高度后，文本编辑区内部滚动，操作区位置保持稳定。

## 12. 智能体配置

- 配置页占据完整应用视图，不嵌入聊天主视图。
- 页面侧边导航、标题栏和画布使用 `#171716` 一体化融合。
- 内部配置主面板使用与聊天主视图一致的大半径圆角。
- 标题使用“智能体”，返回操作使用“返回”。
- 身份区域头像高度与名称、备注两个输入框总高度保持一致。
- 修改配置自动生效时显示“提示：修改自动生效”。
- 添加智能体保留弹窗流程，提供取消和确定按钮，并明确区分添加与修改。

## 13. 图标与动效

- 一个界面只使用项目既有图标家族，不手绘新的功能图标。
- 同一级别按钮的图标使用统一视觉尺寸和 stroke。
- 动效只用于状态切换、消息入场和必要反馈。
- 禁止 hover 位移、click 缩放和无意义循环动画。
- 所有动效遵循 `prefers-reduced-motion`。

## 14. 响应式与无障碍

- 桌面端优先，但关键操作在窄窗口中必须可达。
- 交互目标建议不小于 36px，移动端不小于 44px。
- 图标按钮必须提供可读的 `aria-label`。
- 文字与背景保持 WCAG AA 对比度。
- 弹窗支持 Escape 关闭和正确的焦点返回。
- 键盘用户必须能够识别当前焦点，但焦点反馈不得使用外发光。

## 15. 实现与验收

全局规则优先使用语义类与 CSS 变量：

- `.agenthub-menu`：所有菜单浮层。
- `.agenthub-focus-ring`：输入或组合控件的焦点容器，当前规范不绘制外圈。
- `.agenthub-row-more`：列表行尾更多按钮。
- `.agenthub-chat-composer`：聊天输入区。

每次 UI 修改至少检查：

1. 默认、hover、active、focus-visible、disabled 和 loading 状态。
2. 是否出现位移、重复按钮、边缘发光或透明穿透。
3. 菜单是否无边框、阴影紧凑、菜单项间距正确。
4. 深色主题下文字、背景和控件对比度。
5. 真实桌面窗口中的滚动、弹窗和菜单定位。
6. 相关组件测试、TypeScript 检查和生产构建。

## 16. 文档迭代规则

- 本文档版本随代码演进，不按 Phase 归档。
- 新增全局组件规范时，直接修改对应章节。
- 推翻已有规则时，在“变更记录”中说明原因和影响面。
- 局部例外必须写入组件章节，不能只留在 CSS 注释中。
- 每季度或发生大型视觉调整后进行一次重复规则和过时规则清理。
