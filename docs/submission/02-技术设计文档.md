# AgentHub 技术设计文档

## 1. 技术目标

AgentHub 的技术目标是构建一个可运行、可扩展、可审计的多 Agent 协作平台。系统不仅要能完成普通聊天，还要支持真实 CLI Agent 进程、Project workspace、文件读写、任务调度、产物预览、桌面端本机能力和 SaaS 云端扩展。

核心技术原则：

1. AgentHub 是 CLI Wrapper 调度壳，不是裸调 HTTP LLM API 的聊天壳。
2. Project 是所有会话、文件、产物和执行记录的组织边界。
3. Orchestrator 负责多 Agent 协作调度，普通 Agent 负责具体执行。
4. Artifact 是 Agent 产物的标准回流形态。
5. 本机桌面版和 SaaS 云端版共享核心领域模型，但运行环境不同。

## 2. 总体架构

```text
前端 React / Tauri / SaaS Web / Mobile
  ↓
FastAPI API Gateway
  ↓
Service 业务层
  ↓
Domain 领域层：Orchestrator / ContextManager / Workspace / Artifact
  ↓
Infrastructure：CLI Adapter / EventBus / Runtime Provider / File Storage
  ↓
Data：SQLite / SQLAlchemy / Cloud Workspace Metadata
```

| 层 | 技术 |

## 4. 前端设计

前端采用 IM 式三栏布局：

```text
Project / Session 侧栏
  ├── Project 列表
  ├── 单聊 / 群聊会话
  └── 设置与环境入口

Chat 主区域
  ├── 消息流
  ├── Agent 输出
  ├── 执行过程
  ├── Artifact 卡片
  └── 输入框 / 回复 / 引用 / Pin

预览与弹窗区域
  ├── Artifact 预览
  ├── 文件编辑器
  ├── Diff 视图
  └── 运行过程全屏查看
```

前端重点模块：

| 模块 | 说明 |
| --- | --- |
| ChatWindow | 聊天主界面、消息渲染、输入、执行状态。 |
| CollaborationPanel | 群聊协作计划和 DAG 执行状态展示。 |
| ArtifactCard | 消息级产物卡片。 |
| Artifact Preview / Editor | 文件预览、网页预览、版本和 Diff。 |
| Stores | chat、sessions、projects、artifacts 等领域状态。 |
| API Client | 类型化 REST、SSE、WebSocket 客户端。 |

## 5. 后端设计

后端采用 FastAPI 分层架构：

| 层 | 职责 |
| --- | --- |
| API | 请求校验、REST/SSE/WebSocket 路由、错误映射。 |
| Service | 会话、消息、Agent、任务、Artifact、Workspace、部署等业务逻辑。 |
| Domain | Orchestrator、ContextManager、计划、任务状态机等纯逻辑。 |
| Infrastructure | CLI 进程、文件系统、事件总线、runtime provider。 |
| Data | SQLAlchemy 模型、SQLite 数据库、迁移脚本。 |

后端关键能力：

1. Session 和 Message 持久化。
2. Project workspace 绑定。
3. 单聊和群聊消息上下文构建。
4. CLI Agent 进程启动、输出解析和中止。
5. Orchestrator 计划生成和 DAG 执行。
6. Artifact 创建、版本管理和预览。
7. SaaS 云端 workspace、团队、权限、快照和部署能力。

## 6. Agent Runtime：CLI Wrapper

AgentHub 的 Agent 接入方式是项目最核心的架构点。

系统不把普通 HTTP LLM API 包装成 Agent，而是通过 PTY/subprocess 启动真实 CLI 工具，例如 Claude Code、Codex、OpenCode。每个 CLI 由独立 Adapter 适配其输出格式和交互方式。

```text
用户消息
  ↓
ContextManager 构建上下文
  ↓
Agent Profile 选择 Engine
  ↓
CLI Adapter 启动真实进程
  ↓
stdout / stderr / event stream
  ↓
标准化 agent.output / artifact.created / interactive_prompt
  ↓
前端聊天流和 Artifact
```

CLI Adapter 解决的问题：

| 问题 | 处理方式 |
| --- | --- |
| 不同 CLI 输出格式不一致 | 每个 CLI 独立 Adapter。 |
| 输出包含 ANSI 控制符 | 统一清洗后进入事件流。 |
| CLI 需要交互确认 | 转换为前端可审批的交互提示。 |
| Agent 修改了文件 | 通过 workspace diff 和 Artifact Bridge 回流。 |
| 长任务需要取消 | 后端维护 run/task/process 状态并终止进程。 |

## 7. Agent Profile 模型

Agent 不是单纯模型名，而是一个完整 Profile：

```text
Agent Profile =
  System Prompt
  + Rules
  + Toolset
  + Context Policy
  + Runtime Config
  + Engine
```

这样可以把“产品经理”“前端工程师”“测试工程师”等 Agent 做成可配置联系人，而不是在代码里硬编码角色逻辑。

## 8. Orchestrator 调度设计

Orchestrator 是群聊中的特殊 Agent，负责从用户意图到执行计划的转换。

主要流程：

```text
用户需求
  ↓
意图分析
  ↓
任务拆解
  ↓
Agent 匹配
  ↓
DAG 计划生成
  ↓
用户审批 / 人工干预
  ↓
Scheduler 执行
  ↓
Agent 输出汇总
```

设计重点：

1. 任务拆解粒度是模块级或交付物级，不拆成“创建文件、写函数”这种过细步骤。
2. 计划可以包含人机确认环节。
3. 执行过程中保留暂停、中止、恢复和直接对齐能力。
4. 每个任务有工作包和交接内容，便于后续 Agent 接续。
5. 群聊界面展示任务状态、依赖关系、执行过程和最终汇总。

## 9. Project Workspace 模型

AgentHub 采用 Project-first 工作流：

```text
Project
  ├── workspace_path 或 cloud workspace id
  ├── sessions
  ├── agents
  ├── artifacts
  ├── tasks
  └── deployments
```

本机版 Project 绑定本机目录，CLI Agent 以该目录作为 `cwd` 执行。SaaS 版 Project 使用云端 workspace id，前端不暴露服务器物理路径。

优势：

1. Agent 有明确工作目录。
2. 聊天上下文和文件变更归属清晰。
3. Artifact、快照、部署可以追溯到 Project。
4. 本机版和 SaaS 版可以共享领域模型。

## 10. Artifact 产物链路

Artifact 是 Agent 产物的标准形态。

```text
Agent 执行
  ↓
文件变化 / 代码块 / 预览地址 / 部署状态
  ↓
ArtifactService
  ↓
artifact.created 事件
  ↓
消息级 Artifact 卡片
  ↓
预览 / 编辑 / Diff / 版本 / 引用
```

Artifact 能力包括：

| 能力 | 说明 |
| --- | --- |
| 消息级卡片 | 产物跟随具体 Agent 消息展示。 |
| 文件预览 | 查看 Agent 创建或修改的文件。 |
| 网页预览 | 对前端产物进行页面预览。 |
| 版本链 | 记录 Artifact 的版本演进。 |
| Diff | 对比不同版本或文件变更。 |
| 编辑 | 在预览界面继续编辑代码或内容。 |
| 部署 | SaaS 云端可生成访问链接。 |

## 11. 桌面端设计

桌面端基于 Tauri v2，定位是本地特权层：

1. 启动本地 AgentHub 后端。
2. 打开本地前端 WebView。
3. 允许访问本机 workspace。
4. 管理本机 CLI Agent 进程。
5. 关闭窗口时释放后端进程和端口。

桌面端支持通过双击 exe 体验完整本机链路，不需要手动启动前后端。

## 12. SaaS 云端设计

SaaS 版把本机能力扩展到云端：

| 能力 | 说明 |
| --- | --- |
| Team / RBAC | 支持团队、成员、角色和权限边界。 |
| Cloud Workspace | Project 对应云端隔离 workspace。 |
| 仓库导入 | 支持导入仓库作为云端 workspace 起点。 |
| 快照恢复 | workspace 可创建快照并恢复。 |
| Cloud Runtime | Agent 在云端 runtime 中执行。 |
| 云端 Artifact | 产物保存在云端并可预览。 |
| 一键部署 | 生成可访问部署链接。 |
| 移动端审批 | 移动端用于轻量查看和审批预览。 |

## 13. 测试与质量保障

项目采用分层测试：

| 类型 | 工具 | 覆盖 |
| --- | --- | --- |
| 后端单元/API 测试 | pytest | Service、API、数据库、运行状态。 |
| 前端组件测试 | vitest | ChatWindow、store、交互状态。 |
| 类型检查 | TypeScript | 前端类型安全。 |
| E2E 测试 | Playwright | 真实浏览器交互和关键用户路径。 |
| 真实服务验收 | 本地启动前后端 | API、前端、代理、Artifact、桌面端行为。 |
