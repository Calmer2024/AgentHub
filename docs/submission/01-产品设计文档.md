# AgentHub 产品设计文档

## 1. 产品定位

AgentHub 是一个 IM 式多 Agent 协作平台。它把 AI Agent 设计成“聊天对象”，让用户可以通过单聊、群聊和 Orchestrator 调度来完成真实项目任务。

传统 AI 编程工具通常是“一个用户对一个模型”的问答模式，复杂任务需要用户反复拆分、复制上下文、检查文件变化。AgentHub 的目标是把这个过程产品化：用户只需要在项目里发起需求，系统负责维护上下文、分派 Agent、展示执行过程，并把产物以可预览、可编辑、可部署的方式返回给用户。

一句话概括：

> AgentHub 是 AI 版的 Slack，把多个 AI Agent 拉到同一个项目群聊里，让它们围绕真实 workspace 协作产出。

## 2. 目标用户

| 用户 | 需求 |
| --- | --- |
| 独立开发者 | 希望用多个 AI Agent 快速完成前端、后端、文档、测试等任务。 |
| 小团队负责人 | 希望把需求拆解、工程执行、审查和验收集中在同一个协作界面里。 |
| AI 工具探索者 | 希望比较 Claude Code、Codex、OpenCode 等真实 Agent 工具的能力。 |

## 3. 核心场景

### 3.1 单聊 Agent

用户在 Project 下创建一个单聊会话，选择一个 Agent，例如“前端工程师”或 Codex。Agent 以当前 Project workspace 为工作目录，可以读取、修改、生成项目文件，并把执行结果返回聊天流。

适合场景：

- 修改一个 React 组件。
- 解释一段后端代码。
- 生成一个页面原型。
- 编写单元测试。

### 3.2 群聊协作

用户在群聊中提出一个复杂目标，例如“帮我做一个宠物护理预约页”。Orchestrator 负责理解意图、拆分任务、生成计划，并把任务交给产品经理、架构师、前端工程师、后端工程师、测试工程师等 Agent。

适合场景：

- 从需求到实现的完整功能开发。
- 多角色协作讨论。
- 需要人机确认的计划执行。
- 需要跨前端、后端、测试的任务。

### 3.3 产物预览与编辑

Agent 的输出不只是文本。代码变更、网页预览、文件内容、Diff 和部署状态会以 Artifact 形式出现在消息下方。用户可以直接预览、编辑、查看版本和继续追问。

### 3.4 桌面端本机工作流

桌面端用于本机文件访问和本机 CLI Agent 进程管理。用户双击桌面端即可启动本地后端和前端界面，在本机 workspace 中完成真实文件读写。

### 3.5 SaaS 云端工作流

SaaS 云端版面向团队协作和云端产物交付。它支持云端 workspace、团队、仓库导入、快照恢复、云端 Agent Runtime、云端预览和一键部署访问链接。SaaS 版把本机版的 Project/Session/Agent/Artifact 模型扩展到云端环境。

## 4. 产品信息架构

AgentHub 采用 Project-first 工作流：

```text
Project
  ├── 单聊 Session
  ├── 群聊 Session
  ├── Agent Profile
  ├── Workspace 文件
  ├── Artifact 产物
  └── 执行记录 / 快照 / 部署
```

用户必须先进入 Project，再创建单聊或群聊。这样所有 Agent 都围绕同一个 workspace 工作，避免“聊天在一处、文件在另一处”的割裂体验。

## 5. 关键产品能力

| 能力 | 设计说明 |
| --- | --- |
| Project-first | 每个任务有明确 workspace，聊天、文件、产物和执行记录都归属于 Project。 |
| 单聊 | 用于明确、小范围任务，强调上下文连续和真实文件执行。 |
| 群聊 | 用于复杂任务，通过 Orchestrator 分派多个 Agent 协作。 |
| Orchestrator | 负责意图理解、计划生成、任务拆解、DAG 调度和结果汇总。 |
| Agent Profile | Agent 由 System Prompt、Rules、Toolset、Context Policy、Runtime Config 和 Engine 组成。 |
| CLI Agent 接入 | 接入 Claude Code、Codex、OpenCode 等真实 CLI Agent。 |
| Artifact | 把代码、文件、网页预览、Diff、版本和部署状态转化为消息级产物。 |
| Human-in-the-loop | 计划、审批、暂停、恢复、直接对齐等环节保留用户干预能力。 |
| 多端形态 | Web 是主力端用于连接SaaS服务，桌面端负责本机权限和进程，移动端负责轻量查看、审批和预览。 |
| SaaS 云端 | 云端 workspace、团队协作、仓库导入、快照恢复、云端预览和部署链接。 |

## 6. 核心用户链路

### 6.1 本机桌面版链路

1. 用户启动桌面端。
2. 创建 Project，绑定本机 workspace。
3. 创建单聊或群聊。
4. 用户发送任务。
5. Agent 在 workspace 中执行。
6. 聊天流展示执行过程和结果。
7. Artifact 卡片展示文件、Diff 或预览。
8. 用户继续追问、编辑、审批或导出。

### 6.2 SaaS 云端版链路

1. 用户登录 SaaS Web。
2. 创建团队或进入已有团队。
3. 创建云端 Project。
4. 导入仓库或创建云端 workspace。
5. 在云端 session 中调用 Agent。
6. 云端 runtime 执行任务并生成产物。
7. 用户查看云端预览、快照和部署访问链接。

## 9. 产品亮点

1. **IM 范式自然**：用户不需要学习复杂工作流工具，用聊天即可驱动任务。
2. **真实 Agent 进程**：通过 CLI Wrapper 调用真实工具，而不是简单模型 API 包装。
3. **Project-first**：聊天、文件、产物、执行记录围绕同一个 workspace 闭环。
4. **多 Agent 群聊**：把复杂任务拆成多角色协作流程。
5. **Artifact 回流**：Agent 产物不是散落在文件系统里，而是回到消息流中可预览、可编辑。
6. **桌面与云端兼容**：本机版强调稳定执行和本地权限，SaaS 版扩展团队、云端 workspace 和部署。
7. **AI 协作沉淀充分**：项目开发过程本身就是可展示的 AI 协作方法论。

## 10. 后续规划

1. 继续提升 SaaS 群聊调度与本机版体验的一致性。
2. 强化云端 sandbox 隔离、资源限制和部署 provider。
3. 扩展更多 Artifact 类型，例如 PPT、数据表和交互式原型。
4. 增强团队协作中的评论、通知、审批和审计体验。
5. 完善移动端审批、预览和轻量回复链路。
