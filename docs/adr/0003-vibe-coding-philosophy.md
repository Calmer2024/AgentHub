# ADR-0003: Vibe Coding 开发规则

**日期**: 2026-05-25
**状态**: Accepted

## 背景
避免传统 vibe coding 容易导致的代码混乱、后期不可维护的问题，同时保留快速迭代的优势。

## 决策
采用 **"架构打底 + 快速迭代 + 测试护航"** 的结构化 vibe coding 模式：

1. **先做顶层架构设计**：动手写代码之前，先把核心模块划分、接口定义、数据流图定下来
2. **分模块逐个突破**：按照架构图一个模块一个模块地开发
3. **每个模块完成后立即写单元测试**：保证模块交付质量
4. **小步提交，每日快照**：随时可以回滚

禁止"完全没有设计直接开写"的野蛮模式。

## 影响
- 前期投入少量设计时间，后期开发不会进入重构地狱
- 代码质量有底线，项目可长期维护
- 依然保持快速迭代的 vibe coding 节奏
